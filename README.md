# 门店酒水盘查

这是一个本地优先的门店酒水盘查工具：员工每天只需填写实物剩余库存，系统保存前一营业日销量、进货、凌晨回加项与盘差。数据默认保存在本机浏览器；云端同步为可选能力，未配置时可用 JSON 数据包交接。

## 凌晨盘点口径

凌晨 1 点盘点“昨天”时，昨天销量只取昨天 00:00–23:59:59 的完整营业日销量。此时柜内实物已经少了新一天的酒水，因此要单独记录两类回加项：

1. `00点后已结账`：新一天 00:00 到盘点时刻已结账的酒水。
2. `未结账桌已拿酒`：仍在用餐、已拿走但尚未结账的酒水。

系统计算：

`昨日盘差 = 昨日期初 + 昨日进货 − 昨日销量 − (实物剩余 + 00点后已结账 + 未结账桌已拿酒)`

两项回加均不写入昨天销量。第二天的期初库存继承上述核账余量，避免跨日重复漏算。

## 每日执行流程

1. 凌晨进入“酒水盘点”，切换到“昨天”。
2. 从美团管家复制昨天完整的“酒水饮料”明细，粘贴并写入昨天销量。未知品项会阻止写入，必须先确认映射。
3. 逐项填写柜内、库房等实际剩余数量；即使为 0 也要明确填写。
4. 在“凌晨盘点回加项”填写 00 点后已结账销量，以及未结账桌已拿酒数量；有多项变化时可粘贴“品名 空格 数量”，系统只接受统一品名。
5. 查看异常品项；核实后保存日盘。需要跨设备交接时，到“数据同步”导出或提交。
6. 新一天的期初会继承昨日核账余量；不要把凌晨回加项再当作昨天销量重复填写。

## 数据边界

- 页面中的 OCR、销量文本解析和云端同步均为辅助能力，最终提交前必须人工核对。
- 不要把浏览器本地数据当作真实后端备份；重要日盘应导出数据包或完成云端提交。
- 接入美团或 POS 时应使用正式授权 API 或稳定导出文件，并保留原始来源、时间和更正记录。
