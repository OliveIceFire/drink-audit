# 云端同步实施说明

## 目标

员工端每天只填写每个酒水品项的实盘剩余数量。系统自动带入期初、入库和“昨天完整营业日”的销售快照，计算差异并让管理端查看。

## 数据来源优先级

1. 美团官方授权 API。
2. 美团管家导出的昨日“酒水饮料”销售文件。
3. 管理员人工核验并导入的销售数据。

网页浏览器自动化只能用于辅助核验，不作为正式账源。

## 每日流程

1. 凌晨任务锁定昨天 `00:00–23:59:59` 的销售快照，拒绝覆盖；更正必须新增来源记录。
2. 根据前一天已锁定核账余量生成今日期初：`实物余量 + 00点后已结账 + 未结账桌已拿酒`。
3. 同步入库、报损、赠送等库存变动。
4. 员工填写 `actual_remaining`；凌晨盘点时另填 `after_midnight_sales_quantity` 与 `open_table_quantity`，提交后生成差异。
5. 差异非零、库存为负、销量异常或连续差异时通知管理端。
6. 管理员复核后将日盘锁定，所有后续修改写入 `audit_events`。

## 部署顺序

1. 创建 Supabase 项目并执行 `schema.sql`。
2. 执行 `access_control.sql`，建立门店成员与 RLS 策略；员工仅可提交所属门店当天余量，管理者可查看门店与锁定日盘。
3. 执行只读的 `verify_rollout.sql`：确认 10 张表均启用 RLS、策略数大于 0、匿名策略数为 0、活动品项数为 26。
4. 在受控服务端配置美团正式数据源；若未获 API 权限，配置每日导出文件解析任务。
5. 前端接入认证与 API，停用 JSON 手工传递作为常规路径，仅保留为离线备份。

## 准确性要求

- 销售快照必须保存原始文件/原始响应和导入时间。
- 菜品先经别名字典归一化，未匹配品项进入待处理队列，不能静默计为零。
- 每个销售快照都校验分页总量、品项数和金额合计。
- 日盘提交前校验所有售卖品项均已填实盘余量。
# 酒水盘查云端数据

1. 先在 Supabase SQL Editor 执行 `schema.sql`，并选择 **Run and enable RLS**。
2. 再执行 `seed_pilot_store.sql`：它会创建试点门店、26 个盘查品项，以及已核对的美团销售名称映射。
3. 记录输出的门店 ID，填入本地 `cloud-config.js`；浏览器中只能使用 Supabase anon key，绝不能使用 service-role key。

当前 RLS 已开启但尚未授予员工权限。下一步必须接入员工身份与门店成员关系后，再开放跨设备提交；这可避免任何匿名用户读写盘查数据。
